# متریکا — راهنمای نصب روی هاست لینوکس نت‌افراز (DirectAdmin)

این بسته همان نسخهٔ تأییدشدهٔ متریکاست؛ طراحی، صفحه‌ها، انیمیشن‌ها و رسپانسیو هیچ تغییری نکرده‌اند. فقط سه چیز به آن اضافه شده است:

- بک‌اند واقعی **PHP + MySQL** برای ورود با پیامک؛
- اتصال به **فراز اس‌ام‌اس** (ارسال با پترن)؛
- آماده‌سازی فایل‌ها برای هاست اشتراکی.

## دو فایل تحویلی

| فایل | چیست | کجا استفاده می‌شود |
|---|---|---|
| `METRICA_HOST_READY.zip` | وب‌اپ کامل: صفحه، فایل‌های جانبی (CSS، JavaScript، تصاویر، فونت Estedad)، بک‌اند PHP، تنظیمات خصوصی و جدول‌های دیتابیس | هاست واقعی؛ طبق همین راهنما |
| `index.html` (مستقل) | همان وب‌اپ در **یک فایل** که همهٔ تصاویر، فونت‌ها و کدها داخل خودش است و به هیچ فایل دیگری نیاز ندارد | فقط برای دیدن و نمایش ظاهر روی هر کامپیوتر یا گوشی |

> **نسخهٔ مستقل بک‌اند ندارد.** در آن ورود و ثبت‌نام کار نمی‌کند: با زدن «دریافت کد تأیید» فقط پیام «ارسال کد تأیید پس از فعال‌سازی سرویس پیامک در دسترس خواهد بود.» می‌آید. هیچ درخواستی به اینترنت نمی‌رود و چیزی ذخیره نمی‌شود. برای سایت واقعی فقط از ZIP استفاده کنید.

## ساختار ZIP

```
METRICA_HOST_READY.zip
├── public_html/              ← تنها بخشی که از اینترنت دیده می‌شود
│   ├── index.html            صفحهٔ وب‌اپ (۱۲۲ کیلوبایت)
│   ├── .htaccess             امنیت (CSP، منع فهرست پوشه‌ها و فایل‌های مخفی) و کش
│   ├── assets/               css · js · img · fonts (نام هر فایل با محتوایش عوض می‌شود)
│   └── api/index.php         درِ ورود API؛ فقط فایل‌های پوشهٔ خصوصی را صدا می‌زند
├── metrica_private/          ← خصوصی: کنار public_html، نه داخل آن
│   ├── config.php            دیتابیس، کلید فراز اس‌ام‌اس، شناسهٔ پترن
│   ├── app/                  کد بک‌اند (قوانین OTP، اتصال پیامک، API)
│   └── .htaccess             اگر اشتباهی در public_html قرار بگیرد، همه‌چیز را رد می‌کند
├── database/schema.sql       جدول‌های MySQL (از وب دیده نمی‌شود)
└── README-FA.md              همین راهنما (از وب دیده نمی‌شود)
```

**چرا نام پوشه `private` نیست:** DirectAdmin پوشه‌ای به نام `private_html` دارد که برای HTTPS عمومی است. برای اینکه این دو با هم اشتباه گرفته نشوند، پوشهٔ خصوصی متریکا `metrica_private` نام دارد.

ZIP پوشهٔ بیرونی ندارد. وقتی آن را داخل پوشهٔ دامنه Extract کنید، `public_html` با محتوای متریکا پر می‌شود و `metrica_private`، `database` و این راهنما **کنار** آن قرار می‌گیرند. یعنی همه‌چیز با یک Extract سر جای خودش می‌نشیند.

## پیش‌نیازها

- **PHP نسخهٔ ۷٫۴ یا بالاتر** (پیشنهاد: ۸٫۱ یا بالاتر) با افزونه‌های `pdo_mysql` و `curl`. این‌ها در هاست‌های نت‌افراز معمولاً فعال‌اند. نسخهٔ PHP در DirectAdmin از بخش «PHP Version Selector» یا «Select PHP version» تنظیم می‌شود.
- **MySQL یا MariaDB.**
- **گواهی SSL (HTTPS).** پنل ورود فقط از راه HTTPS با سرور حرف می‌زند؛ روی http ورود غیرفعال می‌ماند.

## ۱. کدام فایل‌ها داخل `public_html` قرار می‌گیرند

1. وارد DirectAdmin شوید و **File Manager** را باز کنید.
2. به این مسیر بروید: `domains` ← `نام‌دامنهٔ‌شما` (همان پوشه‌ای که `public_html` داخل آن است).
3. اگر در `public_html` فایل‌های پیش‌فرض هاست هست (مثل `index.html` خوشامدگویی DirectAdmin)، آن‌ها را پاک کنید یا بگذارید Extract رویشان بنویسد.
4. فایل `METRICA_HOST_READY.zip` را با **Upload** در همین پوشه (`domains/نام‌دامنه/`) آپلود کنید.
5. روی ZIP راست‌کلیک کنید، **Extract** را بزنید و مقصد را همین پوشه بگذارید. اگر پرسید فایل‌های موجود جایگزین شوند، تأیید کنید.
6. بعد از Extract، فایل ZIP را پاک کنید.

داخل `public_html` فقط این‌ها قرار می‌گیرند: `index.html`، `.htaccess`، پوشهٔ `assets` و پوشهٔ `api`.

> فایل `.htaccess` با نقطه شروع می‌شود و ممکن است در File Manager مخفی باشد. اگر گزینهٔ «Show hidden files» هست، آن را روشن کنید و مطمئن شوید این فایل در `public_html` وجود دارد.

## ۲. پوشهٔ خصوصی دقیقاً کجا باشد

باید **کنار** `public_html` باشد، نه داخل آن:

```
/home/نام‌کاربری/domains/نام‌دامنه/
├── public_html/
├── metrica_private/     ← اینجا
├── database/
└── README-FA.md
```

اگر طبق مرحلهٔ ۱ Extract کرده باشید، پوشه همین‌جاست و کاری لازم نیست.

اگر هاست شما ساختار دیگری دارد (مثلاً `public_html` مستقیم در `/home/نام‌کاربری/` است)، `metrica_private` را کنار **همان** `public_html` بگذارید. فایل `public_html/api/index.php` همیشه آن را در مسیر `public_html/../metrica_private` پیدا می‌کند.

## ۳. ساخت دیتابیس MySQL و وارد کردن فایل SQL

1. در DirectAdmin به **MySQL Management** بروید و **Create new Database** را بزنید.
2. نام دیتابیس و نام کاربر را وارد کنید (DirectAdmin نام کاربری هاست را خودش ابتدای آن‌ها می‌گذارد، مثلاً `user_metrica`) و یک رمز قوی بسازید. **هر سه مقدار را یادداشت کنید.**
3. از همان صفحه یا از لینک phpMyAdmin، **phpMyAdmin** را باز کنید و از ستون چپ دیتابیس تازه را انتخاب کنید.
4. سربرگ **Import** را باز کنید و فایل `database/schema.sql` را انتخاب کنید (ZIP را روی کامپیوتر خودتان هم باز کنید تا این فایل را داشته باشید). سپس **Go** را بزنید.
5. باید پنج جدول ساخته شود: `mt_users`، `mt_sessions`، `mt_otp_requests`، `mt_otp_events` و `mt_otp_locks`.

اجرای دوبارهٔ این فایل ضرری ندارد؛ جدول‌های موجود را دست نمی‌زند.

## ۴. اطلاعات دیتابیس در کدام فایل

فایل **`metrica_private/config.php`**. در File Manager روی آن راست‌کلیک کنید، **Edit** را بزنید و این چهار خط را پر کنید:

```php
const DB_HOST = "localhost";
const DB_NAME = "PASTE_DB_NAME_HERE";      ← نام کامل دیتابیس، مثل "user_metrica"
const DB_USER = "PASTE_DB_USER_HERE";      ← نام کامل کاربر دیتابیس
const DB_PASS = "PASTE_DB_PASSWORD_HERE";  ← رمز کاربر دیتابیس
```

`DB_HOST` در هاست‌های DirectAdmin تقریباً همیشه `localhost` است. فقط عبارت بین دو کوتیشن `"…"` را عوض کنید و کوتیشن‌ها و `;` آخر خط را نگه دارید.

## ۵. محل Paste کردن API Key و Pattern UID

در **همان فایل** `metrica_private/config.php` این دو خط هست. فقط مقدار داخل کوتیشن را جایگزین کنید:

```php
const API_KEY = "PASTE_YOUR_API_KEY_HERE";
const PATTERN_UID = "PASTE_YOUR_PATTERN_UID_HERE";
```

برای پیدا کردنشان در File Manager یا ویرایشگر، `PASTE_YOUR_API_KEY_HERE` و `PASTE_YOUR_PATTERN_UID_HERE` را جست‌وجو کنید.

- **API Key:** از پنل فراز اس‌ام‌اس (panel.iranpayamak.com)، بخش وب‌سرویس یا کلید API.
- **Pattern UID:** شناسهٔ پترنی که برای کد ورود ساخته و تأیید شده است.
- **متغیر پترن باید دقیقاً `code` باشد.** نمونهٔ متن پترن:
  ```
  کد ورود شما به متریکا: %code%
  این کد را به کسی ندهید.
  ```
  اگر متغیر پترن شما نام دیگری دارد، به‌جای عوض کردن پترن مقدار `SMS_PATTERN_VARIABLE` را در همین فایل به همان نام تغییر دهید.
- **اختیاری — پر شدن خودکار کد در اندروید:** اگر خط آخر پترن به این شکل باشد، کروم اندروید کد را خودش وارد می‌کند. دامنه را دامنهٔ واقعی سایت بگذارید:
  ```
  @metrica.ir #%code%
  ```
  در آیفون این خط لازم نیست؛ پر شدن خودکار کد بدون آن هم کار می‌کند.

این مقدارها از قبل تنظیم شده‌اند و نیازی به وارد کردن ندارند:

| ثابت | مقدار |
|---|---|
| `SMS_API_URL` | `https://api.iranpayamak.com/ws/v1/sms/pattern` |
| `SMS_SENDER` | `09820002022` |
| `number_format` | `english` |

ارسال فوری است و `schedule` فرستاده نمی‌شود.

> کلید API فقط در همین فایل خصوصی است. در HTML، JavaScript، لاگ یا هیچ فایل عمومی‌ای نیست و به مرورگر کاربر هم نمی‌رسد. این فایل را جایی منتشر نکنید و از آن نسخهٔ پشتیبان بگیرید. مقدار `APP_SECRET` همان فایل برای همین بسته ساخته شده است؛ بعد از راه‌اندازی آن را تغییر ندهید.

## ۶. فعال شدن سرویس OTP

کلید جداگانه‌ای برای روشن کردن لازم نیست. OTP خودکار فعال می‌شود، به شرطی که هر سه شرط زیر برقرار باشد:

1. اطلاعات دیتابیس درست باشد و جدول‌ها ساخته شده باشند (مراحل ۳ و ۴)؛
2. `API_KEY` و `PATTERN_UID` مقدار واقعی داشته باشند (مرحلهٔ ۵)؛
3. سایت روی **HTTPS** باز شود:
   - در DirectAdmin به **SSL Certificates** بروید و گواهی Let's Encrypt بگیرید؛
   - گزینهٔ «Use a symbolic link from private_html to public_html» را روشن کنید؛
   - گزینهٔ **Force SSL with https redirect** را فعال کنید.

**بررسی:** این آدرس را باز کنید (دامنهٔ خودتان را بگذارید):

```
https://دامنه‌ی‌شما/api/index.php/health
```

| پاسخ | معنی |
|---|---|
| `"otp":"active"` | همه‌چیز آماده است |
| `"database":"not-configured"` | مرحلهٔ ۴ انجام نشده |
| `"database":"error"` | نام، کاربر یا رمز دیتابیس اشتباه است |
| `"schema":"missing"` | مرحلهٔ ۳ (Import) انجام نشده |
| `"sms":"not-configured"` | مرحلهٔ ۵ انجام نشده |
| `"php":"missing curl or pdo_mysql"` | افزونهٔ PHP را از پشتیبانی هاست بخواهید |

این آدرس هیچ اطلاعات محرمانه‌ای نشان نمی‌دهد. اگر `config.php` را تازه ویرایش کرده‌اید و پاسخ عوض نشده، چند ثانیه صبر کنید؛ PHP فایل‌ها را با کمی تأخیر دوباره می‌خواند.

تا وقتی این سه شرط برقرار نشده، هیچ پیامکی ارسال نمی‌شود، هیچ کدی ساخته نمی‌شود و مرحلهٔ دوم ورود باز نمی‌شود. کاربر فقط پیام «ارسال کد تأیید پس از فعال‌سازی سرویس پیامک در دسترس خواهد بود.» را می‌بیند.

## ۷. آزمایش ارسال و تأیید واقعی کد

1. سایت را روی `https://` باز کنید و **ورود / ثبت‌نام** را بزنید.
2. شمارهٔ موبایل خودتان را وارد کنید، تیک قوانین را بزنید و **دریافت کد تأیید** را بزنید.
3. باید پیامک برسد، مرحلهٔ دوم باز شود و تایمر از `۰۲:۰۰` شروع کند.
4. کد را وارد کنید. با کامل شدن چهار رقم، کد خودکار بررسی می‌شود.
5. برای شمارهٔ تازه، فرم نام و نام خانوادگی می‌آید. بعد از ثبت، نام شما در «حساب من» دیده می‌شود.
6. صفحه را رفرش کنید؛ باید وارد حساب باقی بمانید.

**فهرست آزمون پیش از انتشار:**

| سناریو | نتیجهٔ درست |
|---|---|
| کد اشتباه | پیام «کد واردشده صحیح نیست. لطفاً آن را بررسی و اصلاح کنید.»، ارقام می‌مانند، کادرها قرمز می‌شوند و تعداد تلاش باقی‌مانده نمایش داده می‌شود |
| رفرش در مرحلهٔ دوم | تایمر از اول شروع نمی‌شود و ادامه پیدا می‌کند |
| «ارسال مجدد کد» | تا پایان ۲ دقیقه غیرفعال است و بعد فعال می‌شود |
| بعد از ۲ دقیقه | کد قبلی دیگر پذیرفته نمی‌شود |
| ۵ تلاش اشتباه روی یک کد | آن کد قفل می‌شود و کد جدید لازم است |
| ۷ تلاش اشتباه در ۱۰ دقیقه | تا زمان اعلام‌شده (با شمارش معکوس) قفل می‌ماند؛ کد جدید یا رفرش آن را باز نمی‌کند |
| ششمین درخواست کد در ۱۰ دقیقه | رد می‌شود و زمان مجاز بعدی نمایش داده می‌شود |

**اگر پیامک نرسید:**

- فایل `metrica_private/logs/app.log` را در File Manager باز کنید. پاسخ فراز اس‌ام‌اس آنجا ثبت می‌شود، مثلاً کلید نامعتبر، پترن تأییدنشده یا اعتبار کافی نیست. کلید API و شمارهٔ کامل در این لاگ نوشته نمی‌شوند و لاگ از وب قابل دیدن نیست.
- در پنل فراز اس‌ام‌اس بخش گزارش ارسال‌ها را ببینید.
- اگر پنل فراز برای استفاده از API محدودیت IP دارد، IP سرور هاست را در آن مجاز کنید.

## ۸. انتقال از دامنهٔ آزمایشی به دامنهٔ اصلی

در کد هیچ دامنه یا مسیری ثابت نوشته نشده است: آدرس API نسبی است و همیشه کنار `index.html` قرار دارد. برای همین انتقال فقط جابه‌جایی فایل‌هاست:

1. در DirectAdmin دامنهٔ اصلی را اضافه کنید (Domain Setup) یا اگر لازم است دامنهٔ آزمایشی را تغییر نام دهید.
2. در File Manager، پوشه‌های `public_html` و `metrica_private` را از `domains/دامنه‌ی‌آزمایشی/` به `domains/دامنه‌ی‌اصلی/` کپی کنید. **ساختار باید همان بماند**: `metrica_private` کنار `public_html`.
3. `config.php` را دست نزنید. همان دیتابیس، همان کلید و همان `APP_SECRET` بمانند تا کاربران و تنظیمات حفظ شوند.
4. برای دامنهٔ اصلی SSL بگیرید و **Force SSL** را روشن کنید.
5. اگر خط پر شدن خودکار (`@دامنه #%code%`) را در پترن گذاشته‌اید، دامنهٔ آن را در پنل فراز به دامنهٔ اصلی تغییر دهید.
6. آدرس `https://دامنه‌ی‌اصلی/api/index.php/health` را بررسی کنید و یک بار ورود را آزمایش کنید.
7. در آخر، فایل‌های دامنهٔ آزمایشی را پاک کنید یا آن دامنه را به دامنهٔ اصلی Redirect کنید.

حساب‌ها در دیتابیس می‌مانند. فقط چون کوکی هر دامنه جداست، کاربرانی که روی دامنهٔ آزمایشی وارد شده بودند روی دامنهٔ اصلی یک بار دیگر وارد می‌شوند.

## امنیت در این بسته

- **قوانین OTP همه در سرور و اتمیک‌اند:**
  - کد ۴ رقمی تصادفی با ۱۲۰ ثانیه اعتبار، که فقط HMAC آن ذخیره می‌شود؛
  - کد تازه فقط بعد از پایان کد قبلی؛
  - برای هر شماره ۵ درخواست و ۷ تلاش ناموفق در هر پنجرهٔ متحرک ۱۰ دقیقه‌ای؛
  - ۵ تلاش برای هر کد؛
  - سقف جداگانه برای IP و دستگاه؛
  - قفل ردیفی در MySQL، تا درخواست‌های هم‌زمان نتوانند از سقف عبور کنند.
- **نشست:** کوکی `HttpOnly` و `SameSite=Lax` که روی HTTPS با `Secure` ساخته می‌شود. در دیتابیس فقط هش توکن نگه داشته می‌شود و در مرورگر هیچ کد یا توکنی ذخیره نمی‌شود.
- **CSRF:** درخواست‌های POST فقط با هدر مخصوص وب‌اپ و فقط از همان دامنه پذیرفته می‌شوند.
- **`.htaccess`:**
  - CSP بدون اجازهٔ اسکریپت درون‌خطی؛
  - منع قرار گرفتن سایت در iframe و منع حدس نوع فایل؛
  - بسته بودن فهرست پوشه‌ها، فایل‌های مخفی، `.sql`، `.md` و `.log`؛
  - کش یک‌ساله برای `assets` (نام فایل‌ها با محتوا عوض می‌شود) و بازبینی همیشگی `index.html`.
- **پشت CDN یا پراکسی** (مثل ابر آروان یا Cloudflare): در `config.php` مقدار `TRUSTED_IP_HEADER` را بگذارید تا IP واقعی کاربران خوانده شود، مثلاً `"HTTP_CF_CONNECTING_IP"` یا `"HTTP_X_FORWARDED_FOR"`.

## آنچه آزمایش شد و آنچه نشد

**آزمایش شد** (روی Apache + PHP 8.3 + MariaDB 10.11 با همین ساختار پوشه‌های DirectAdmin):

- **۴۵ آزمون قوانین OTP** روی MySQL، از جمله درخواست‌های واقعاً هم‌زمان از چند پروسه.
- **۱۲۸ بررسی روی همین بسته:**
  - سالم بودن ZIP؛
  - بارگذاری همهٔ فایل‌ها با نوع و کش درست؛
  - در دسترس نبودن `config.php`، SQL، README و لاگ از وب؛
  - CSP بدون هیچ خطا؛
  - یکسان بودن پیکسل‌به‌پیکسل ظاهر با نسخهٔ تأییدشده در عرض‌های ۳۹۰ و ۱۴۴۰؛
  - غیرفعال ماندن OTP بدون کلید یا بدون دیتابیس؛
  - قالب دقیق درخواست به فراز (روی یک درگاه آزمایشی محلی)؛
  - ثبت خطای درگاه در لاگ خصوصی؛
  - همهٔ سناریوهای مرحلهٔ دوم در مرورگر؛
  - ذخیرهٔ حساب‌ها در MySQL؛
  - HttpOnly بودن کوکی‌ها؛
  - ماندن در حساب پس از رفرش.
- **۱۹۰ بررسی** نسخهٔ مستقل و رسپانسیو در ۱۴ اندازهٔ صفحه.

**آزمایش نشد:**

- ارسال پیامک واقعی با فراز اس‌ام‌اس، چون کلید واقعی در دسترس نبود (مرحلهٔ ۷ همین آزمون است).
- خود سرور نت‌افراز. اگر وب‌سرور آن LiteSpeed باشد، قواعد `.htaccess` همین‌طور اعمال می‌شوند؛ با این حال بعد از نصب، آدرس health و مرحلهٔ ۷ را انجام دهید.
