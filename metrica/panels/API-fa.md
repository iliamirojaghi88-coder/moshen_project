# متریکا — APIهای لازم برای فعال‌سازی ورود، اشتراک و سهمیه‌ها

قرارداد بین فرانت‌اند (`AuthService` و `SubscriptionService` در `panels.js`) و بک‌اند. همهٔ آدرس‌ها نسبت به `METRICA_CONFIG.apiBase` هستند.

## قواعد عمومی

- فقط **HTTPS**. بدنه‌ها JSON. فرانت‌اند همهٔ درخواست‌ها را با `credentials: 'include'` و هدر `X-Metrica-Client: web` می‌فرستد.
- **نشست**: کوکی `HttpOnly; Secure; SameSite=Lax` (یا `Strict`) که فقط سرور می‌سازد و می‌خواند. هیچ توکنی در بدنهٔ پاسخ برای ذخیره در مرورگر برنگردانید.
- **CORS** (اگر API روی دامنهٔ دیگری است): `Access-Control-Allow-Origin` دقیقاً برابر دامنهٔ وب‌اپ (نه `*`)، `Access-Control-Allow-Credentials: true`، `Access-Control-Allow-Headers: Content-Type, X-Metrica-Client`.
- **CSRF**: درخواست‌های POST بدون هدر `X-Metrica-Client` یا با Origin ناشناخته رد شوند.
- **خطا**: وضعیت HTTP مناسب و بدنهٔ `{ "error": "<CODE>", "retryAfter"?: <ثانیه>, "attemptsLeft"?: <عدد> }`. فرانت‌اند هدر `Retry-After` را هم می‌خواند. مهلت هر درخواست در فرانت‌اند ۱۵ ثانیه است.

| کد خطا | HTTP | پیام نمایش‌داده‌شده |
|---|---|---|
| `SERVICE_UNAVAILABLE` | 503 | سرویس پیامک / درگاه پرداخت هنوز فعال نیست |
| `INVALID_PHONE` | 400 | شماره موبایل معتبر نیست |
| `RATE_LIMITED` | 429 | تعداد درخواست‌ها بیش از حد مجاز است |
| `INVALID_CODE` | 400 | کد اشتباه + `attemptsLeft` |
| `TOO_MANY_ATTEMPTS` | 429 | تلاش‌ها تمام شد؛ کد جدید لازم است |
| `CODE_EXPIRED` | 410 | کد منقضی شده است |
| `UNAUTHORIZED` | 401 | نشست معتبر نیست |
| هر خطای دیگر / 5xx | — | خطای سرور |
| قطع شبکه / مهلت | — | اتصال به سرور برقرار نشد |

## ۱. احراز هویت با OTP

### `GET /auth/session`
در بارگذاری صفحه صدا زده می‌شود.
- وارد شده: `200 { "user": User }` — وارد نشده: `200 { "user": null }` (برای اینکه کنسول مرورگر خطای 401 نشان ندهد).

### `POST /auth/otp/request`
`{ "phone": "09123456789" }` (همیشه ۱۱ رقم انگلیسی، نرمال‌شده)
- `200 { "requestId": "…", "expiresIn": 120, "resendIn": 60 }`
  - `expiresIn`: ثانیه تا انقضای کد — **دقیقاً ۱۲۰**. تایمر فرانت‌اند از همین مقدار و لحظهٔ دریافت پاسخ شمرده می‌شود (مستقل از ساعت گوشی).
  - `resendIn`: ثانیه تا مجاز شدن «ارسال مجدد کد» (سیاست سرور؛ اگر نیاید برابر `expiresIn` فرض می‌شود).
- قواعد سرور:
  - کد ۴ رقمی تصادفی امن (CSPRNG)، ذخیره به‌صورت hash، عمر ۱۲۰ ثانیه.
  - صدور کد جدید برای یک شماره، **کد قبلی را باطل می‌کند**.
  - محدودیت نرخ برای **شماره، دستگاه و IP** (مثلاً هر شماره ۱ پیامک در ۶۰ ثانیه و حداکثر ۵ در ساعت؛ هر IP و دستگاه سقف جدا) → `429 RATE_LIMITED` با `retryAfter`.
  - پاسخ برای شمارهٔ ثبت‌نشده و ثبت‌شده یکسان باشد (افشای عضویت نشود).
  - متن پیامک برای پر شدن خودکار (WebOTP در اندروید) با خط آخر به این شکل: `@app.metrica.ir #1234` (دامنهٔ واقعی وب‌اپ).
  - تا وقتی سرویس پیامک تنظیم و آزمایش نشده: `503 SERVICE_UNAVAILABLE` — فرانت‌اند در مرحلهٔ اول می‌ماند و پیام مربوط را نشان می‌دهد.

### `POST /auth/otp/verify`
`{ "requestId": "…", "code": "1234" }`
- موفق، کاربر قبلی: `200 { "user": User }` + ساخت نشست (Set-Cookie).
- موفق، کاربر جدید: `200 { "profileRequired": true, "user": { … } }` + نشست محدود که فقط اجازهٔ `POST /auth/profile` دارد.
- کد اشتباه: `400 { "error": "INVALID_CODE", "attemptsLeft": n }`.
- حداکثر **۵ تلاش ناموفق** برای هر `requestId`؛ پس از آن `429 { "error": "TOO_MANY_ATTEMPTS", "retryAfter": s }` و درخواست کد جدید لازم است.
- منقضی: `410 { "error": "CODE_EXPIRED" }`. کد پس از یک بار استفادهٔ موفق باطل شود.

### `POST /auth/profile`
`{ "firstName": "…", "lastName": "…" }` (هر کدام حداکثر ۴۰ نویسه؛ سرور اعتبارسنجی و پاک‌سازی کند)
- `200 { "user": User }` و ارتقای نشست به نشست کامل.

### `POST /auth/logout`
`{}` → `200 {}` و حذف کوکی نشست. (دکمهٔ «خروج از حساب» هنوز به این وصل نشده است.)

### `User`
```json
{ "id": "…", "firstName": "سارا", "lastName": "محمدی", "name": "سارا محمدی", "avatar": "https://…", "plan": "normal | plus | pro | max" }
```
شمارهٔ موبایل لازم نیست به فرانت‌اند برگردد. فرانت‌اند `name`، `avatar` و `plan` را به `Metrica.setUser` می‌دهد.

## ۲. اشتراک و پرداخت

### پلن‌ها (منبع قطعی قیمت: سرور)
| شناسه | نام | کاربران | دسترسی | سهمیه | قیمت |
|---|---|---|---|---|---|
| `plus` | پلاس / Plus | ۱ | آنالیز ساخت | ۱ پروژه در هر ۲۴ ساعت | ۵۰۰٬۰۰۰ تومان |
| `pro` | پرو / Pro | ۱ | آنالیز ساخت، مدیریت پروژه | ۳ پروژه در هر ۲۴ ساعت | ۱٬۰۰۰٬۰۰۰ تومان |
| `max` | MAX | تا ۵ | همهٔ امکانات (آنالیز ساخت، مدیریت پروژه، کش‌فلو، مارکتینگ) | ۵ پروژه در هر ۲۴ ساعت | ۵٬۰۰۰٬۰۰۰ تومان |

دورهٔ زمانی اشتراک (ماهانه/سالانه) در داده‌های پروژه مشخص نشده و در رابط نمایش داده نمی‌شود؛ پس از تعیین، به متن پلن‌ها اضافه شود.

### `POST /subscription/checkout`
`{ "plan": "plus" | "pro" | "max" }` — فقط با نشست معتبر (وگرنه `401`).
- `200 { "paymentUrl": "https://…" }` → فرانت‌اند کاربر را به درگاه می‌برد (فقط آدرس HTTPS پذیرفته می‌شود).
- مبلغ را سرور از شناسهٔ پلن تعیین می‌کند؛ هیچ مبلغی از فرانت‌اند پذیرفته نشود.
- تا اتصال درگاه: `503 SERVICE_UNAVAILABLE`.
- بازگشت از درگاه (callback) و تأیید تراکنش (verify) فقط سمت سرور؛ پس از تأیید، اشتراک فعال و کاربر به وب‌اپ برگردانده شود. فعال‌سازی اشتراک هرگز بر اساس پارامتر آدرس بازگشت انجام نشود.
- کلیدهای درگاه فقط در سرور.

### `GET /subscription`
`200 { "plan": "max", "status": "active | expired | none", "expiresAt": "…", "seats": { "limit": 5, "used": 2 }, "quota": Quota }`

### اعضای MAX (حداکثر ۵ کاربر) — پیشنهادی
- `GET /subscription/members` · `POST /subscription/members { "phone": "09…" }` · `DELETE /subscription/members/:id`
- سقف ۵ نفر را سرور اعمال کند (`409 { "error": "SEATS_FULL" }`).

## ۳. سهمیهٔ پروژه‌ها (پنجرهٔ ۲۴ ساعته)

### `Quota`
```json
{ "limit": 3, "used": 1, "windowHours": 24, "mode": "rolling | fixed", "windowStart": "…", "resetsAt": "…" }
```
- `limit`: ۱ / ۳ / ۵ بر اساس پلن.
- `mode` در تنظیمات بک‌اند قابل تغییر است:
  - `rolling`: هر پروژه ۲۴ ساعت پس از ثبت، سهمیه را آزاد می‌کند.
  - `fixed`: پنجره از اولین استفاده (یا ساعت ثابت، مثلاً ۰۰:۰۰ تهران) شروع و ۲۴ ساعت بعد کامل تمدید می‌شود.
- در MAX سهمیه برای کل اشتراک (۵ کاربر) مشترک یا برای هر کاربر — تصمیم و پیکربندی سمت سرور.

### `GET /quota` → `200 Quota`
### ثبت پروژه / آنالیز
هر endpoint که پروژه یا آنالیز جدید می‌سازد پیش از اجرا سهمیه و اعتبار اشتراک را **سمت سرور** بررسی کند و در صورت پر بودن: `429 { "error": "QUOTA_EXCEEDED", "resetsAt": "…" }`. محدودسازی صرف در JavaScript کافی نیست.
