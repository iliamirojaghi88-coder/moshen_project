# سیم‌لند (SIMLAND) — وب‌سایت معرفی محصولات سیم و کابل

وب‌سایت ایستا، فارسی و راست‌به‌چپ با هیروی سه‌بعدی تعاملی. بدون فریم‌ورک و بدون CDN؛ تنها کتابخانه‌ی بیرونی Three.js است که به‌صورت محلی و بهینه‌شده در `assets/vendor/` قرار دارد.

## خروجی نهایی: یک فایل

**`dist/index.html`** کل وب‌سایت در یک فایل است (حدود ۱٫۴ مگابایت):
- همه CSS داخل `<style>` است.
- همه جاوااسکریپت، از جمله Three.js و صحنه سه‌بعدی، داخل یک `<script>` است.
- فونت Estedad، تصاویر محصولات و پوسترهای جایگزین به‌صورت داخلی (data URI) جاسازی شده‌اند.

فایل هیچ درخواست بیرونی ندارد. با دوبار کلیک مستقیم در مرورگر باز می‌شود، یا می‌توانید همین یک فایل را روی هر هاست بگذارید.

خانه و محصولات دو «نما» در همین یک صفحه هستند:

| آدرس | نما |
| --- | --- |
| `#/` | خانه: هیرو، محصولات، چرا سیم‌لند، ارتباط با ما |
| `#/products` | صفحه محصولات: ۱۰ محصول، ارتباط با ما |
| `#/products/armoured` | صفحه محصولات با نمای جزئیات همان محصول باز |
| `#contact` | بخش ارتباط با ما در نمای فعلی |

دکمه بازگشت مرورگر بین نماها جابه‌جا می‌شود و نمای جزئیات را می‌بندد.

برای توسعه، `index.html` در ریشه همین صفحه است با فایل‌های جدا در `assets/`، و به سرور محلی نیاز دارد:

```bash
cd sites/simland
python3 -m http.server 8765        # http://127.0.0.1:8765/index.html
node tools/build-pages.mjs         # ساخت دوباره index.html و dist/index.html
```

## ساختار

```
dist/index.html       ← خروجی نهایی تک‌فایلی
index.html            همان صفحه برای توسعه (فایل‌های assets/ را جدا بارگذاری می‌کند)
assets/css/           style.css (پایه و اجزا) · responsive.css (چیدمان هر اندازه صفحه)
assets/js/
  main.js             هدر، منوی موبایل، بخش فعال منو، اطلاعات تماس، راه‌اندازی صحنه سه‌بعدی
  router.js           دو نمای خانه و محصولات، آدرس‌ها و دکمه بازگشت
  animations.js       نمایش تدریجی، ورود عمقی کارت‌ها، پارالاکس، چرخش کارت، دکمه‌های مغناطیسی
  products.js         نمای جزئیات محصول (dialog، پیوند مستقیم، دکمه بازگشت مرورگر)
  site-config.js      ← اطلاعات تماس (تنها جای ویرایش)
  hero3d/             صحنه سه‌بعدی: stage.js (دوربین و اسکرول)، cable-model.js (مدل کابل)، studio.js (نور استودیو)، geometry.js
assets/vendor/        three.min.js (فقط بخش‌های استفاده‌شده از Three.js، برای نسخه توسعه)
assets/fonts/         فونت متغیر Estedad (woff2) + مجوز OFL
assets/images/        products/ (WebP در سه اندازه) · hero/ (پوستر جایگزین)
source/               عکس‌های اصلی (products/)، mapping.json، retouch.json، نسخه‌های استاندارد شفاف (standardized/)
src/                  قالب صفحه و بخش‌های مشترک (هدر، فوتر، تماس، …)
tools/                اسکریپت‌های ساخت
```

## ویرایش‌های رایج

**اطلاعات تماس** — `assets/js/site-config.js`. مقدار واقعی را وارد کنید و `active: true` بگذارید تا دکمه به لینک تماس، ایمیل یا واتساپ تبدیل شود. تا وقتی `active: false` است، هیچ لینکی به شماره‌ی آزمایشی ساخته نمی‌شود.

**جابه‌جایی عکس محصولات** — `source/mapping.json` مشخص می‌کند کدام عکس (به ترتیب ارسال: `photo-01` تا `photo-10`) متعلق به کدام محصول است. بعد از ویرایش:

```bash
python3 tools/standardize-products.py   # استانداردسازی و ساخت PNG شفاف هر محصول
node tools/build-images.mjs             # ساخت WebP‌های سایت
node tools/build-pages.mjs              # ساخت دوباره index.html و dist/index.html
```

## استانداردسازی تصاویر محصولات

عکس‌های اصلی در `source/products/` دست‌نخورده می‌مانند؛ نسخه‌های استاندارد در فایل‌های جدا ساخته می‌شوند.

1. **انتهای کابل** — پنج عکس (۰۱، ۰۲، ۰۴، ۰۶، ۰۹) انتهای طبیعی و بیضوی دارند. انحنای آن‌ها اندازه‌گیری شد (نسبت ارتفاع به عرض بیضی ۰٫۴۴۵ تا ۰٫۵۰۷) و با میانگین ۰٫۴۸ به‌عنوان استاندارد ثبت شد. چهار عکس (۰۳، ۰۷، ۰۸، ۱۰) از کادر بیرون می‌زدند و عکس ۰۵ انتهای صاف و تخت داشت. برای این پنج عکس، روکش در فاصله‌ی یک قطر کابل از لبه‌ی بالایی (مثل عکس‌های مرجع) با همان بیضی بسته شد. پرداخت لبه هم مثل عکس‌های مرجع است: افت ملایم نور، سایه‌ی باریک لبه و خط نازک نور روی لبه. هیچ پیکسلی نقاشی یا ساخته نشده؛ فقط روکش موجود در همان عکس روی بیضی تمام شده است. تنظیمات هر عکس در `source/retouch.json` است. در عکس ۰۷ (آلومینیومی) طول روکش در خود عکس کمتر بود، پس انتها تا جایی که عکس اجازه می‌داد پایین آمد.
2. **جداسازی از زمینه** — چون زمینه‌ی همه عکس‌ها مشکی خالص است، شفافیت هر پیکسل از روی نسبت روشنایی آن به رنگ محصول در همان نقطه محاسبه می‌شود. خروجی: `source/standardized/<slug>.png` (PNG شفاف). این فایل روی زمینه‌ی مشکی دقیقاً همان پیکسل‌های عکس اصلی را برمی‌گرداند (اختلاف میانگین کمتر از ۰٫۰۵ از ۲۵۵). شکاف‌های کاملاً مشکیِ محصور بین رشته‌ها کدر می‌مانند؛ در این رندرها زمینه و سایه‌ی عمیق هر دو مشکی خالص‌اند و قابل تفکیک نیستند.
3. **چیدمان یکسان** — `tools/build-images.mjs` همه محصولات را روی بوم ۸۸۰×۱۱۰۰ (۴:۵) با ارتفاع یکسان (۸۰٪ بوم) و حاشیه‌ی بالا و پایین برابر قرار می‌دهد. نسبت طول و عرض هیچ محصولی تغییر نمی‌کند.

برگه‌های کنترل کیفیت (قبل/بعد، و نمایش روی زمینه‌ی مشکی، سفید و خاکستری) با اجرای اسکریپت در `source/standardized/qc/` ساخته می‌شوند. این پوشه در git نگهداری نمی‌شود.

**متن‌ها و بخش‌های مشترک** — در `src/` ویرایش کنید و `node tools/build-pages.mjs` را اجرا کنید. هر تغییری در `assets/` (CSS، JS، تصاویر) هم بعد از اجرای همین دستور وارد `dist/index.html` می‌شود.

**توضیح هر محصول** — نمای جزئیات فعلاً فقط تصویر، نام و دکمه‌های استعلام را نشان می‌دهد؛ هیچ مشخصات فنی یا قیمتی اختراع نشده است.

## اسکریپت‌های ساخت

نیاز به Node.js 18+ و بسته‌های ریشه‌ی مخزن (`sharp`، `esbuild`، `three`).

| اسکریپت | کار |
| --- | --- |
| `tools/standardize-products.py` | بستن انتهای کابل‌ها با بیضی استاندارد، جداسازی از زمینه، PNG شفاف، برگه‌های QC (Python 3 + numpy، Pillow، OpenCV) |
| `tools/build-images.mjs` | چیدمان یکسان روی بوم ۴:۵ مشکی، خروجی WebP در ۴۴۰/۶۶۰/۸۸۰ پیکسل |
| `tools/build-pages.mjs` | ساخت `dist/index.html` (تک‌فایلی، همه‌چیز داخلی) و `index.html` (نسخه توسعه) از `src/` و `source/mapping.json` |
| `tools/build-vendor.mjs` | ساخت `three.min.js` فقط با بخش‌هایی که کد صحنه import می‌کند |
| `tools/render-posters.mjs` | رندر پوسترهای جایگزین از همان صحنه‌ی سه‌بعدی (نیاز به Playwright و سرور محلی) |

## صحنه سه‌بعدی

- مدل کابل کاملاً رویه‌ای ساخته می‌شود (بدون فایل مدل): روکش PVC با چاپ «SIMLAND / سیم‌لند»، زره سیم فولادی گالوانیزه، بستر داخلی، چهار رشته با عایق قهوه‌ای/مشکی/خاکستری/آبی (IEC) و هادی مسی ۱۹ رشته‌ای با تاب لایه‌ای مخالف و باز شدن طبیعی سر رشته‌ها.
- نور: استودیوی رویه‌ای (سافت‌باکس‌ها) که یک‌بار به نقشه‌ی محیطی PMREM تبدیل می‌شود.
- یک renderer و یک WebGL context برای کل صفحه؛ بوم بین هیرو و بخش «چرا سیم‌لند» جابه‌جا می‌شود و وقتی دیده نمی‌شود رندر متوقف است.
- کیفیت تطبیقی: هندسه و متریال سبک‌تر روی موبایل و دستگاه‌های ضعیف، سقف DPR، و کاهش خودکار وضوح اگر فریم‌ها کند شوند.
- بدون WebGL یا با اینترنت کند، پوستر رندرشده از همان صحنه نمایش داده می‌شود.
- با «کاهش حرکت» (Reduced Motion) سیستم‌عامل: بدون انیمیشن ورود، کابل ثابت با صفحه اسکرول می‌شود و نمایش‌های تدریجی خاموش‌اند.

## پشتیبانی مرورگر

Chrome/Edge 111+، Safari 16.4+، Firefox 115+ (به‌خاطر import map، `dialog` و `inert`). انتقال تصویر کارت به نمای جزئیات (View Transitions) در مرورگرهایی که پشتیبانی نمی‌کنند با یک انیمیشن ساده جایگزین می‌شود.
