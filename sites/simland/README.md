# سیم‌لند (SIMLAND) — وب‌سایت سیم و کابل

وب‌سایت ایستا، فارسی و راست‌به‌چپ با جهان سه‌بعدی تعاملی. بدون فریم‌ورک و بدون CDN؛ تنها کتابخانه‌ی بیرونی Three.js است که به‌صورت محلی و بهینه‌شده در `assets/vendor/` قرار دارد.

## خروجی نهایی: یک فایل

**`dist/index.html`** کل وب‌سایت در یک فایل است:
- همه CSS داخل `<style>` است.
- همه جاوااسکریپت، از جمله Three.js و صحنه‌های سه‌بعدی، داخل یک `<script>` است.
- فونت Estedad، تصاویر محصولات، رندرها، آیکون‌های سه‌بعدی و پوسترهای جایگزین به‌صورت داخلی (data URI) جاسازی شده‌اند.

فایل هیچ درخواست بیرونی ندارد. با دوبار کلیک مستقیم در مرورگر باز می‌شود، یا می‌توانید همین یک فایل را روی هر هاست بگذارید.

سه صفحه‌ی مستقل در همین یک فایل هستند:

| آدرس | صفحه |
| --- | --- |
| `#/` | خانه: هیروی سه‌بعدی بی‌نهایت، ۱۰ محصول، چرا سیم‌لند، دعوت به مشاوره، فوتر |
| `#/products` | محصولات: هیروی کابل آرمودار با برچسب لایه‌ها، دسته‌بندی‌ها، کاتالوگ با فیلتر، جزئیات و استعلام |
| `#/products/armoured` | صفحه محصولات با نمای جزئیات همان محصول باز |
| `#/contact` | ارتباط با ما: دو سر کابل که جریان بینشان برقرار است، راه‌های تماس، مراحل سفارش |

دکمه بازگشت مرورگر بین صفحه‌ها جابه‌جا می‌شود و نمای جزئیات را می‌بندد. بین صفحه‌ها یک پرده‌ی نور رد می‌شود.

برای توسعه، `index.html` در ریشه همین صفحه است با فایل‌های جدا در `assets/`، و به سرور محلی نیاز دارد:

```bash
cd sites/simland
python3 -m http.server 8765        # http://127.0.0.1:8765/index.html
node tools/build-pages.mjs         # ساخت دوباره index.html و dist/index.html
```

## ساختار

```
dist/index.html       ← خروجی نهایی تک‌فایلی
index.html            همان صفحه برای توسعه (فایل‌های assets/ را جدا بارگذاری می‌کند)
assets/css/           style.css (رنگ، نور و اجزا) · responsive.css (چیدمان هر اندازه صفحه)
assets/js/
  main.js             هدر، منوی موبایل، صفحه‌ی فعال منو، اطلاعات تماس، راه‌اندازی صحنه سه‌بعدی و برچسب‌ها
  router.js           سه صفحه، آدرس‌ها، پرده‌ی انتقال و دکمه بازگشت
  animations.js       نمایش تدریجی، ورود عمقی کارت‌ها، پارالاکس، جریان مدار «چرا سیم‌لند»، چرخش کارت، دکمه‌های مغناطیسی
  products.js         نمای جزئیات محصول (dialog، پیوند مستقیم، بازگشت) و فیلتر کاتالوگ
  site-config.js      ← اطلاعات تماس (تنها جای ویرایش)
  hero3d/
    stage.js          یک renderer برای هر سه صفحه؛ دوربین، ورود سینمایی، اسکرول و اشاره‌گر
    infinity-scene.js جهان هیرو: کابل بی‌نهایت با چاپ «سیم‌لند»، کارخانه، توربین‌ها، ویلا، دکل، پنل خورشیدی، درخت و چمن
    cable-geometry.js هندسه‌ی کابل‌ها (آرمودار، ابزار دقیق، تک‌رشته) — منبع مشترک صفحه و Blender
    cable-model.js    کابل‌های صفحه‌ی محصولات و تماس
    materials.js      متریال‌های PBR (مس ناهمسانگرد، PVC، فولاد، فویل) و نورهای محیطی
    geometry.js       ابزار ساخت هندسه
assets/vendor/        three.min.js (فقط بخش‌های استفاده‌شده از Three.js، برای نسخه توسعه)
assets/fonts/         فونت متغیر Estedad (woff2) + مجوز OFL
assets/images/        products/ (WebP شفاف در سه اندازه) · render/ (رندرهای Blender) · icons/ (آیکون‌های سه‌بعدی) · hero/ (پوسترهای جایگزین)
source/               عکس‌های اصلی، mapping.json (نام، ترتیب و دسته‌ی محصولات)، retouch.json، نسخه‌های استاندارد شفاف
src/                  قالب صفحه و بخش‌های مشترک (هدر، فوتر، تماس، دعوت به مشاوره، …)
tools/                اسکریپت‌های ساخت (پایین)
```

## ویرایش‌های رایج

**اطلاعات تماس** — `assets/js/site-config.js`. مقدار واقعی را وارد کنید و `active: true` بگذارید تا دکمه به لینک تماس، ایمیل یا واتساپ تبدیل شود. تا وقتی `active: false` است، هیچ لینکی به شماره‌ی آزمایشی ساخته نمی‌شود. یادداشت «اطلاعات تماس نمونه است» در `src/partials/contact.html` را هم پس از آن حذف کنید.

**نام، ترتیب و دسته‌ی محصولات** — `source/mapping.json`. هر محصول یک `category` دارد (`building`، `industrial`، `special`)؛ متن هر دسته در `categories` همان فایل است.

**جابه‌جایی عکس محصولات** — `source/mapping.json` مشخص می‌کند کدام عکس (به ترتیب ارسال: `photo-01` تا `photo-10`) متعلق به کدام محصول است. بعد از ویرایش:

```bash
python3 tools/standardize-products.py   # استانداردسازی و ساخت PNG شفاف هر محصول
node tools/build-images.mjs             # ساخت WebP‌های سایت
node tools/build-pages.mjs              # ساخت دوباره index.html و dist/index.html
```

**متن‌ها و بخش‌های مشترک** — در `src/` ویرایش کنید و `node tools/build-pages.mjs` را اجرا کنید. هر تغییری در `assets/` (CSS، JS، تصاویر) هم بعد از اجرای همین دستور وارد `dist/index.html` می‌شود.

**توضیح هر محصول** — نمای جزئیات فقط تصویر، نام، دسته و دکمه‌های استعلام را نشان می‌دهد؛ هیچ مشخصات فنی یا قیمتی اختراع نشده است.

## تصاویر محصولات

عکس‌های اصلی در `source/products/` دست‌نخورده می‌مانند. `tools/standardize-products.py` انتهای کابل‌ها را با بیضی استاندارد می‌بندد و هر محصول را از زمینه‌ی مشکی جدا می‌کند (PNG شفاف در `source/standardized/`). `tools/build-images.mjs` همه را روی بوم شفاف ۸۸۰×۱۱۰۰ (۴:۵) با ارتفاع یکسان (۸۰٪ بوم) و حاشیه‌ی برابر قرار می‌دهد؛ صحنه‌ی نورپردازی‌شده (گرادیان، درخشش و سایه‌ی کف) را خود کارت می‌سازد. نسبت طول و عرض هیچ محصولی تغییر نمی‌کند.

## رندرها و آیکون‌های سه‌بعدی (Blender)

رندرهای «مقطع کابل»، «ماکروی مس»، «سینی کابل» و پنج آیکون شیشه‌ای/مسی «چرا سیم‌لند» با Blender (Cycles) از **همان هندسه‌ی کابل صفحه** ساخته می‌شوند. نور از HDRI استودیویی `studio_small_09` (Poly Haven، CC0) می‌آید. این تصاویر نمایشی‌اند و به‌عنوان محصول واقعی سیم‌لند معرفی نشده‌اند.

```bash
node tools/export-cables.mjs /tmp/cables                       # هندسه‌ی کابل‌ها → OBJ
blender -b --factory-startup -P tools/blender/render-imagery.py -- macro /tmp/cables /tmp/renders/macro.png
#   شات‌ها: macro، section، tray، icon-quality، icon-variety، icon-price، icon-support، icon-delivery
node tools/build-imagery.mjs /tmp/renders                      # PNG → WebP سایت
```

## صحنه‌های سه‌بعدی

- **خانه:** کابل تخت سفید به شکل بی‌نهایت؛ در یک حلقه کارخانه با دودکش‌ها، توربین‌های بادی و تپه‌ی چمن، در حلقه‌ی دیگر ویلای مدرن، دکل انتقال برق و پنل خورشیدی. سر کابل در جلو باز است: هادی مسی رشته‌ای و عایق‌های رنگی. «سیم‌لند» با بافت روی روکش چاپ شده و با سطح کابل خم می‌شود (عنصر HTML نیست).
- **حرکت:** ورود سینمایی دوربین، توربین‌های چرخان، چمن در باد، واکنش به اشاره‌گر، و با اسکرول دوربین به سمت سر مسی کابل می‌رود و صفحه‌ی محصولات روی صحنه بالا می‌آید.
- **محصولات:** کابل آرمودار که آرام می‌چرخد؛ برچسب‌های هادی، عایق، زره و روکش لایه‌ها را دنبال می‌کنند و وقتی لایه پشت کابل می‌رود پنهان می‌شوند.
- **تماس:** دو سر کابل روبه‌روی هم و درخشش جریان بینشان.
- یک renderer و یک WebGL context برای هر سه صفحه؛ وقتی صحنه دیده نمی‌شود، تب پنهان است یا نمای جزئیات باز است، رندر متوقف است.
- کیفیت تطبیقی: هندسه، چمن و درخت سبک‌تر و نقشه‌ی سایه‌ی کوچک‌تر روی موبایل و دستگاه‌های ضعیف، سقف DPR، و کاهش خودکار وضوح اگر فریم‌ها کند شوند.
- بدون WebGL یا با اینترنت کند، پوستر رندرشده از همان صحنه‌ها نمایش داده می‌شود (`tools/render-posters.mjs`).
- با «کاهش حرکت» (Reduced Motion) سیستم‌عامل: بدون ورود سینمایی، پرده‌ی انتقال و نمایش‌های تدریجی؛ صحنه‌ها ثابت‌اند و فقط با اسکرول دوباره کشیده می‌شوند.

## اسکریپت‌های ساخت

نیاز به Node.js 18+ و بسته‌های ریشه‌ی مخزن (`sharp`، `esbuild`، `three`).

| اسکریپت | کار |
| --- | --- |
| `tools/standardize-products.py` | بستن انتهای کابل‌ها، جداسازی از زمینه، PNG شفاف، برگه‌های QC (Python 3 + numpy، Pillow، OpenCV) |
| `tools/build-images.mjs` | چیدمان یکسان روی بوم شفاف ۴:۵، خروجی WebP در ۴۴۰/۶۶۰/۸۸۰ پیکسل |
| `tools/export-cables.mjs` | خروجی OBJ از هندسه‌ی کابل‌ها برای Blender |
| `tools/blender/render-imagery.py` | رندر Cycles رندرها و آیکون‌های سه‌بعدی |
| `tools/build-imagery.mjs` | تبدیل رندرهای Blender به WebP سایت |
| `tools/build-vendor.mjs` | ساخت `three.min.js` فقط با بخش‌هایی که کد صحنه import می‌کند |
| `tools/render-posters.mjs` | رندر پوسترهای جایگزین از همان صحنه‌های سه‌بعدی (Playwright و سرور محلی) |
| `tools/build-pages.mjs` | ساخت `dist/index.html` (تک‌فایلی) و `index.html` (توسعه) از `src/` و `source/mapping.json` |

## پشتیبانی مرورگر

Chrome/Edge 111+، Safari 16.4+، Firefox 115+ (به‌خاطر import map، `dialog` و `inert`). انتقال تصویر کارت به نمای جزئیات (View Transitions) در مرورگرهایی که پشتیبانی نمی‌کنند با یک انیمیشن ساده جایگزین می‌شود.
