## ۲. ممیزی امنیتی

**معماری واقعی:** یک صفحه‌ی ایستای تک‌فایلی (HTML + CSS + JS داخلی) و یک PDF. سرور برنامه، API، پایگاه داده، فرم، ورود کاربر، پنل مدیریت و آپلود فایل وجود ندارد. بنابراین SQL/NoSQL Injection، CSRF، IDOR، مدیریت نشست، Rate Limiting، SSRF، Command Injection و CORS **موضوعیت ندارند**. هیچ‌کدام به‌زور اضافه نشد.

| بررسی | یافته | اقدام |
|---|---|---|
| XSS / تزریق DOM | هیچ `innerHTML`، `eval`، `document.write` یا ورودی کاربر در DOM نیست؛ تنها ورودی، آدرس `#/…` است که فقط با فهرست ثابت مسیرها مقایسه می‌شود | — |
| CSP | وجود نداشت | CSP سخت‌گیرانه در `<meta>`: اسکریپت فقط با هش SHA-256، بدون هیچ مبدأ بیرونی، `object`، `<base>` یا مقصد فرم. ۰ نقض روی file://، http:// و نسخه‌ی تک‌فایلی |
| Clickjacking، nosniff، HSTS، Referrer، Permissions | قابل تنظیم از HTML نیست | `.htaccess` (Apache، روی Apache 2.4 آزموده شد)، `_headers` (Netlify/Cloudflare)، `deploy/nginx.conf` |

## ۴. کارایی

- **حجم:** `index.html` حدود ۲۰٫۲ مگابایت است (gzip روی سرور ۱۵٫۱ مگابایت). ۱۰ مگابایت آن عکس‌های کاتالوگ است که فقط هنگام باز شدن صفحه‌ی محصول decode می‌شوند.
- **بارگذاری محلی:** حدود ۰٫۶ ثانیه (بارگذاری و reload اندازه‌گیری شد).
- **هیرو WebGL:** فقط وقتی تصویر روی صفحه و زبانه فعال است رسم می‌کند. در گوشی‌های کند روی ۳۰ فریم می‌ماند. با از دست رفتن context یا بدون WebGL، تصویر ثابت نمایش داده می‌شود.
- **کش:** HTML همیشه بازبینی می‌شود (`no-cache`)، پس نسخه‌ی جدید فوراً دیده می‌شود. PDF هفت روز کش می‌شود.
- **CLS/LCP:** با ابزار جداگانه اندازه‌گیری نشد.
- **SEO:** `lang="fa" dir="rtl"`، title، description و برچسب‌های Open Graph دارد. `canonical` و `og:image` به دامنه‌ی نهایی نیاز دارند.
- **دسترس‌پذیری:** همه‌ی دکمه‌ها و لینک‌ها نام دسترس‌پذیر و همه‌ی ورودی‌ها برچسب دارند؛ tabindex مثبت ندارد.

## ۷. ریسک‌های باقی‌مانده

1. **حجم ۲۰ مگابایتی صفحه‌ی تک‌فایلی:** در اینترنت موبایل کند، بار اول چند ثانیه طول می‌کشد (۱۵ مگابایت gzip روی ۱۰ مگابیت بر ثانیه حدود ۱۲ ثانیه). راه‌حل: نسخه‌ی چندفایلی که فقط تصاویر دیده‌شده را بارگذاری کند. تغییر معماری است و به تأیید شما نیاز دارد.
2. هاستی که دستور `Header` را در `.htaccess` نپذیرد، خطای ۵۰۰ می‌دهد؛ با حذف `.htaccess` رفع می‌شود.
3. `canonical` و `og:image` تا تعیین دامنه اضافه نشده‌اند. مسیرهای `#/…` جداگانه در موتور جست‌وجو ثبت نمی‌شوند.
4. آزمون زمان‌بندی «در انتظار تأمین» در ۷۶۸ زیر بار سنگین یک بار رد شد؛ روی دستگاه واقعی بررسی شود.
5. باگ لایه‌ی روشن پشت عکس‌های کنترل افشان در اولین نمایش در محیط آزمون بازتولید نشد. علت در فایل‌ها رفع شده است؛ روی همان گوشی تأیید شود.
6. مواردی از داده‌های فنی که مرجع متناقض یا ناخوانا بود (سایزهای کابل افشان و کابل قدرت افشان و چند مشخصه‌ی کابل شیلددار بدون میکا) منتشر نشدند (جزئیات در `HANDOFF.md`).
