# گزارش نصب و فعال‌سازی ۵ ابزار/اسکیل سراسری

این سند نتیجهٔ نصب و ثبت ۵ ابزار درخواستی را توضیح می‌دهد. هدف این بود که این ابزارها
**در هر چت و هر نشست (session)** قابل استفاده باشند، نه فقط در یک گفتگو.

## خلاصهٔ وضعیت

| ابزار | منبع واقعی (تصحیح‌شده) | نوع | روش نصب | وضعیت |
|---|---|---|---|---|
| Playwright | `microsoft/playwright` | CLI + MCP | از قبل در ایمیج نصب است + سرور MCP ثبت شد | ✅ فعال |
| unslop | اسکیلِ `unslop` (ریپوی `thevahidal/unslop` وجود ندارد) | Skill | فایل `SKILL.md` ساخته و کامیت شد | ✅ فعال |
| strix | `usestrix/strix` (نه `usmanhalalit/strix`) — پکیج `strix-agent` | Python CLI | `pip install strix-agent` نسخهٔ 1.7.0 | ✅ نصب شد |
| skillUi | `skillui` روی npm (نه `kamranahmedse/skill-ui`) | CLI | `npm install -g skillui` نسخهٔ 1.3.4 | ✅ فعال |
| context7 | `upstash/context7` | MCP server | `@upstash/context7-mcp` ثبت شد | ✅ Connected |

> **توجه دربارهٔ آدرس‌ها:** سه آدرس از پنج آدرسِ داده‌شده روی گیت‌هاب **۴۰۴** بودند
> (`thevahidal/unslop`، `usmanhalalit/strix`، `kamranahmedse/skill-ui`). خودِ ابزارها
> واقعی‌اند ولی زیر نام/صاحبِ دیگری هستند، و همان نسخه‌های واقعی نصب شدند.

## چرا «سراسری» است و فقط محدود به این چت نیست

کانتینرِ ابری در هر نشست از نو ساخته می‌شود، پس برای ماندگاری از **سه لایه** استفاده شد:

1. **اسکیل‌های کامیت‌شده در ریپو** — پوشهٔ `.claude/skills/{playwright,unslop,strix-security,skillui,context7}`.
   این‌ها در **هر چتِ این پروژه** به‌صورت خودکار بارگذاری می‌شوند.
2. **فایل `.mcp.json` در ریشهٔ ریپو** — سرورهای MCP یعنی `context7` و `playwright`
   را در هر نشستِ این پروژه در دسترس می‌گذارد.
3. **اسکریپت راه‌اندازی `scripts/setup-motion-env.sh`** — این اسکریپت با هوک
   `SessionStart` در **هر بار شروعِ نشست** اجرا می‌شود و به‌صورت idempotent:
   - `skillui` و `strix-agent` را در صورت نبودن دوباره نصب می‌کند،
   - سرورهای MCP (`context7`، `playwright`) را در **scope کاربر** دوباره ثبت می‌کند،
   - اسکیل‌ها را در `~/.claude/skills/` هم کپی می‌کند تا در **هر پروژه‌ای که در همین
     environment باز شود** در دسترس باشند (نه فقط این ریپو).

به این ترتیب حتی اگر کانتینر از نو ساخته شود، همه‌چیز خودکار بازسازی می‌شود.

## کاری که برای فعال‌سازی کامل لازم است (یک‌بار، توسط شما)

- **strix** برای اجرا به یک کلید LLM نیاز دارد و فقط باید روی سیستم/کدی اجرا شود که
  **مالک آن هستید یا مجوز کتبی تست دارید**. برای پیکربندی:

  ```bash
  export STRIX_LLM="gemini/gemini-2.5-flash"   # یا openrouter/… یا vercel_ai_gateway/…
  export LLM_API_KEY="<کلید شما>"
  strix --target ./مسیر-پروژه-خودتان
  ```

  Docker در این محیط فعال است، پس پیش‌نیاز اجرایی فراهم است. (هیچ اسکنی به‌صورت
  خودکار اجرا نشده و نمی‌شود؛ اجرا فقط با درخواست صریح شما.)

- **context7** بدون کلید هم کار می‌کند (با سقف نرخِ پایین‌تر). برای سقف بالاتر یک کلید
  رایگان از context7.com بگیرید و با `--api-key` دوباره ثبت کنید یا متغیر
  `CONTEXT7_API_KEY` را تنظیم کنید.

## محدودیت صادقانه دربارهٔ «همهٔ پروژه‌های آینده»

- برای **این پروژه (moshen_project):** پایداری کامل است؛ هر چت و هر نشست هر ۵ ابزار را دارد.
- برای **ریپوهای دیگر:** چون هر نشستِ ابری به یک ریپو گره خورده است، کافی است همین بستهٔ
  پیکربندی (`.claude/skills/`، `.mcp.json`، بخشِ افزوده‌شده به `setup-motion-env.sh`) را
  در آن ریپو هم کپی کنید؛ یا این موارد را در سطحِ **environment** در تنظیمات Claude Code
  وب قرار دهید تا برای همهٔ ریپوهای آن environment اعمال شود.

## اسکیل «شورای Claude» (llm-council)

- **منبع:** `aiwithremy/claude-skills-llm-council` (کامیت `55ee36e`)، ساختهٔ Ole Lehmann،
  بر پایهٔ روش LLM Council کارپاتی. فقط یک فایل `SKILL.md` است (بدون اسکریپت)، و پیش از
  افزودن کامل خوانده شد.
- **مسیر:** `.claude/skills/llm-council/SKILL.md`؛ اسکریپت `setup-motion-env.sh` آن را در هر
  نشست به `~/.claude/skills/` هم کپی می‌کند.
- **تنها تغییر نسبت به نسخهٔ اصلی:** عبارت‌های فارسیِ فراخوانی («شورا رو تشکیل بده»، «شورا را
  تشکیل بده»، «شورا تشکیل بده»، «شورای Claude»، «ببر به شورا») به `description` اضافه شد.
- **روش استفاده:** سؤال یا تصمیم را با جزئیات کسب‌وکار کامل بنویسید و آخرش بگویید
  «شورا رو تشکیل بده (council this)»، یا مستقیم `/llm-council` را بزنید. Claude پنج مشاور
  (Contrarian، First Principles، Expansionist، Outsider، Executor) را موازی اجرا می‌کند،
  پاسخ‌ها را ناشناس داوری متقابل می‌کند و رئیس شورا حکم نهایی را در چت می‌دهد
  (حدود ۱۱ زیرعامل در هر اجرا، پس مصرفش از یک پاسخ معمولی بیشتر است).
- **مجوز:** ریپوی منبع فایل LICENSE ندارد؛ نویسنده آن را برای نصب و استفادهٔ شخصی منتشر کرده است.
